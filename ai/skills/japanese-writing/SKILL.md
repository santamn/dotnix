# 日本語ライティングの振り分け

規範そのものは持たず、**文章のジャンルを決めて、読むべき skill を指す**のがこの skill の役割である。

## ジャンルを決める

書き始める前に下から1つ選ぶ。

| ジャンル | 対象 | 読む skill |
| --- | --- | --- |
| 技術文書 | README、docs/、設計書、API ドキュメント / 短文 (コードコメント、commit message、PR 説明、issue) | `japanese-tech-writing` (短文には「LLM っぽい表現の禁止」と「翻訳調の比喩と擬人化の禁止」の2節だけ当てる) |
| 読み物 | 記事、書籍の章、解説、チュートリアル | `japanese-tech-writing` → `cognitive-rhythm-writing` |
| 個人の文章 | 主観的主張が中心となるブログ記事 | `stop-ai-slop-jp` |

判断に迷ったら、その文章に**書き手個人の立場が重要か**で決める。要るなら個人の文章、要らないなら技術文書とする。`cognitive-rhythm-writing` は自身の冒頭で `japanese-tech-writing` を先に読むよう指示しているので、読み物のときはこの順番を守ること。

## 間違えやすい組み合わせ

- **`cognitive-rhythm-writing` を短文に当てない。** 未回収の緊張や文の拍は、読み進める推進力が要る長さの文章のための道具である。コードコメントや commit message には使えない
- **`stop-ai-slop-jp` を技術文書に当てない。** 「毒を許す」「自虐を残す」「中間温度を混ぜる」「強度を一段下げる」は、書き手個人の立場がある文章でだけ機能する。README や設計書では読みにくくなるだけである

## textlint との分担

語彙と記号の機械的な判定は textlint に寄せてある。規範 skill にも語彙リストはあるが、そちらは「なぜ避けるか」を読むために使い、検出は textlint に任せること。

- textlint が検出する: 偏愛語、全角ダッシュ、中黒での3項目並列、`**` の残骸、コロンの後の半角スペース
- 規範 skill が扱う: false agency、論証の飛躍、命題型 H2、未回収の緊張、立場の不在

`.md` を書いたら `~/.agents/hooks/lint-md.sh <file>` を走らせること。
