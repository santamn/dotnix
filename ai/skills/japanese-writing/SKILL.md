# 日本語ライティングの振り分け

規範そのものは持たない。**ジャンルを決めて、読むべき規範 skill を指すだけ**の skill である。

規範は k16shikano と iKora128 の3本をそのまま使う。抜粋や要約を作ると上流の更新から取り残されるので、ここには置かない。

## ジャンルを決める

書き始める前に下から1つ選ぶ。**技術文書に個人のブログ向けの規範を当てると逆効果になる** (README に毒や自虐や中間温度を入れることになる)。ここが振り分けの主な目的である。

| ジャンル | 対象 | 読む skill |
| --- | --- | --- |
| 技術文書 | README、docs/、設計書、API ドキュメント、コードコメント | `japanese-tech-writing` |
| 読み物 | 記事、書籍の章、解説、チュートリアル | `japanese-tech-writing` → `cognitive-rhythm-writing` |
| 個人の文章 | ブログ、感想、ポエム | `stop-ai-slop-jp` |
| 短文 | commit message、PR 説明、issue | `japanese-tech-writing` の「LLM っぽい表現の禁止」と「翻訳調の比喩と擬人化の禁止」だけ |

判断に迷ったら、その文章に**書き手個人の立場が要るか**で決める。要るなら個人の文章、要らないなら技術文書。

`cognitive-rhythm-writing` は自身の冒頭で `japanese-tech-writing` を先に読むよう指示している。読み物のときは順番を守る。

## 間違えやすい組み合わせ

- **`stop-ai-slop-jp` を技術文書に当てない。** 「毒を許す」「自虐を残す」「中間温度を混ぜる」「強度を一段下げる」は、書き手個人の立場がある文章でだけ機能する。README や設計書では読みにくくなるだけである
- **`cognitive-rhythm-writing` を短文に当てない。** 未回収の緊張や文の拍は、読み進める推進力が要る長さの文章のための道具である。commit message には効かない

## textlint との分担

語彙と記号の機械的な判定は textlint に寄せてある。規範 skill にも語彙リストはあるが、そちらは「なぜ避けるか」を読むために使い、**検出は textlint に任せる**。

- textlint が拾う: 偏愛語、全角ダッシュ、中黒での3項目並列、`**` の残骸、コロンの後の半角スペース
- 規範 skill が扱う: false agency、論証の飛躍、命題型 H2、未回収の緊張、立場の不在

`.md` を書いたら `~/.agents/hooks/lint-md.sh <file>` を走らせる。
